# V2 · 拖拽合成版 24 点 — 技术路线方案

> 目标：把"槽位 + 运算符面板"的交互改为 **拖拽卡牌合成**，背景改为**木质桌面质感**。
> 规则：拖 A 到 B → 选运算 → 合并成一张"合成卡"；可继续把别的卡拖到合成卡上再合并；4 张牌最终合并成 1 张，等于目标（24）即成功。

---

## 一、玩法与交互规则（决策定稿）

1. **开局**：4 张原始数字卡（1–10，带装饰花色），沿用"保证可解"发牌逻辑。
2. **合并**：拖拽卡 A 到卡 B 上 → 弹出**运算选择器**（浮层，定位在两卡之间）：
   - 6 个选项，直接显示实际数值预览：`A+B`、`A−B`、`B−A`、`A×B`、`A÷B`、`B÷A`
   - `+`/`×` 只有一种（交换等价）；`−`/`÷` 给全两种顺序，消除顺序歧义
3. **合成卡**：A、B 消失（A 卡移除，B 位置生成合成卡），数值 = 运算结果，**允许分数**（如 8/3，按 `n/d` 显示，整数直接显示）。
4. **递归合并**：原始卡与合成卡地位相同，都可作为源/目标，直到剩 1 张。
5. **结算（自动，无提交按钮）**：剩 1 张时立即判定——
   - 值 = 目标 → 成功动效 + 得分 +1 + 1.6s 后自动发下一副
   - 值 ≠ 目标 → 抖动红叉 + 提示"结果 X ≠ 24，可撤销重试"，不自动换牌
6. **禁止项**：拖到自身；只剩 1 张时不可再合并；除零合并（如 5÷(3−3)）拒绝并提示。
7. **撤销**：每次合并前压入整副卡组快照，可连续撤销回开局。
8. **提示**：直接复用 solver 的 `makeHint`（"先用 A 和 B 除，得到 8/3"），正好是一条合并建议。
9. **算式轨迹**：桌面下方只读显示当前合并树中缀表达式，随合并实时更新。

## 二、数据模型与核心算法（纯函数，UI 无关，先行落地）

### 卡片对象
```js
{ id, value: { n, d }, tree, kind: 'original' | 'merged' }
```
- `original`：`value={n,d:1}`，`tree={kind:'num', value}`
- `merged`：`value=运算结果`，`tree={kind:'op', op, left, right}`（left/right 为子卡 tree）

### 新增模块
| 文件 | 职责 |
|---|---|
| `src/core/rational.js` | 有理数 `rat/add/sub/mul/div/gcd`，从 solver.js 提取共用（约分、除零返回 null） |
| `src/core/merge.js` | `combine(cardA, cardB, op)` → 新卡或 null；`isSolved(cards,target)`；`formatMergeTree(tree)`（括号正确的中缀串，迁移自 solver.formatTree） |

### 复用与清理
- `solver.js`：改为 import `rational.js`；`hasSolution`/`makeHint` 按原始 4 数逻辑**不变**。
- 删除槽位相关：`expression.js` + `expression.test.js`、`ExpressionArea.vue`、`OperatorPanel.vue`。
- `solver.test.js` 保留，新增 `rational.test.js`、`merge.test.js`。

## 三、状态机改造（useGame.js）

删除 `nums/ops/openBefore/closeAfter` 槽位模型，改为：

```
cards: []                  // 当前卡组（长度 4→1）
history: []                // 整副卡组快照栈（undo）
drag: { sourceId, pointerId, offsetX, offsetY, ghostX, ghostY, hoverTargetId }
pendingMerge: { a, b, x, y }  // 运算选择器：A/B 卡 id + 浮层定位
trace: ''                  // 合并树中缀表达式（只读展示）
target / solved / elapsed / hint / message / fx  // 保留
```

方法：`deal / restart / undo / beginDrag / moveDrag / endDrag / prepareMerge / applyMerge(op) / cancelMerge / hint / startTimer / stopTimer`。

合并后统一走 `afterMerge()`：更新 trace → 检查 `cards.length===1` → 成功/失败结算。

## 四、拖拽实现（可行性最高的方案：Pointer Events）

**不用 HTML5 Drag & Drop API**：不支持触屏、样式/事件跨浏览器差异大。改用 **Pointer Events**，鼠标 + 触屏统一。

```
pointerdown(卡)  → 记录 sourceId + 指针偏移；setPointerCapture；创建跟随指针的半透明"幽灵卡"
pointermove     → 更新幽灵位置；遍历其余卡 getBoundingClientRect 命中检测 → hoverTargetId（命中卡高亮抬起）
pointerup       → 命中目标：弹出运算选择器；未命中：取消拖拽，卡归位
```

- 拖拽中 `touch-action: none` / `preventDefault` 防页面滚动；幽灵卡用 `position: fixed` + `transform` 提升性能。
- 合成卡同样可拖（源/目标均可），递归合并自然实现。

## 九、假设与默认决策

- 运算选择器用 6 选项（消除 `−`/`÷` 顺序歧义），不引入二次"交换顺序"按钮
- 合成结果允许分数，按 `n/d` 显示
- 最终合并即结算，取消"提交"按钮
- 撤销支持连续回退（快照式）
- 木纹用纯 CSS/SVG，不依赖外部图片
- 阶段二/三兼容：`target` 仍是响应式配置，rational/merge/solver 全部按任意目标参数化
